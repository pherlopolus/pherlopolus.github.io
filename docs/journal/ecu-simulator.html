Giving the ECU a simulated engine

Before asking a new ECU to run a motorcycle, it ought to be able to respond sensibly to a fake one.

The CB450 EFI prototype uses a Waveshare ESP32-S3-Touch-LCD-2 as the ECU development board. Its screen can show a large RPM dial and live input bars, with another page for the 9 × 9 RPM/TPS fuel table. A separate, older ESP32 board acts as a simulator: it produces crank pulses and analogue inputs and observes the ECU's logic outputs.

Why two boards?

The simulator makes repeatable situations possible without a running engine: a cold start, idle, cruise, a throttle opening and overrun. It can check whether the ECU responds to a changing input and whether its injector and pump logic is present. The test connections are low-voltage logic; automotive loads need separate protected drivers.

What has been implemented

The v0.5.2 prototype documents Wi-Fi based fuel-map editing, unsaved changes, numbered snapshots and reversion. The web task is separate from the main ECU loop. The display work went through touch diagnostics and changes to reduce full-screen flicker. These are software development milestones; the repository describes the firmware as a bench prototype.

Still to measure: actual temperature sensor curves, injector dead time, input conditioning, output drivers and behaviour under real engine and electrical conditions. No road readiness is claimed.

The useful lesson so far is that a simulator can expose software behaviour early, while the measurements that make it a real engine controller must come from hardware tests.
