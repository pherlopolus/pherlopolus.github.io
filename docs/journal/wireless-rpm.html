An RPM display without a data cable

A separate display lets us watch the RPM experiment without giving the screen a conductive data connection to the test board.

The current standalone pair puts pulse timing on a basic ESP32 and sends calculated measurements to a Waveshare ESP32-S3-Touch-LCD-2 over ESP-NOW. The display has a large RPM readout and a diagnostics page. It distinguishes a stopped engine with a healthy radio link from a lost signal.

What the firmware does

The test board accepts a protected 3.3 V logic pulse, rejects very close edges with a configurable filter, and uses recent pulse intervals for a steadier RPM estimate. Pulses per revolution are configurable and must be checked against the Honda tachometer. The screen shows stale data as a lost signal rather than holding the last apparent RPM indefinitely.

The next physical test

Power the display independently for the initial bike comparison, check the screen and test board against a known pulse source, and then compare both readings with the Honda tachometer. Disconnecting the test board should make the screen report a lost signal; restoring it should recover automatically.

Evidence boundary: the repository describes a build workflow and a first-test procedure. The code's existence and a successful build do not establish that the RPM pickup is accurate on the running bike. The wireless link does not protect the electrical input by itself.

The earlier v1.5.2 package was not available when the v1.6.0 pair was assembled, so this is a standalone matched pair rather than a verified feature-preserving upgrade.
